  • Predictors available before each event
  • A defined prediction period and outcome

1. Welcome to Landslide Atlas

Welcome to Landslide Atlas, an open research workspace for exploring landslide reports in India. This short guide explains how to select a region, inspect evidence, export figures, and begin a reproducible research experiment. The dashboard is an inventory explorer, not an operational warning system or a validated national susceptibility model.

2. Choose a state and district

In the Explore section, choose a state or union territory, then a district. Use the event year and reported trigger filters to narrow the observation record. Decide whether to include reports without a usable date. Read the model availability message. The exploratory Raigad pilot covers only part of that district; selecting another region does not create a trained model there.

3. Read the map carefully

Map points represent reported locations. Select a point or inspect a table entry to review its source, date, and location accuracy. The alternative grid view counts reports in each cell. A darker cell indicates more reports, not a higher estimated failure probability. Missing reports do not prove that an area is safe. Administrative boundaries also have documented source dates and naming limitations.

4. Export figures with provenance

The figures summarize dated reports, reported triggers, reporting geography, and the availability of selected evidence fields. Compare these as patterns in the observation record. Raw counts do not account for surveyed area, exposure, or reporting effort. Export a map or chart as S V G or P N G. Save the filtered C S V or Geo J S O N and the reproduction manifest so another researcher can identify the sources and filters.

5. Add observations and share a project

The Add observations section accepts a location and supporting source details. Record the source and reuse permission, and check the coordinates and date. Your observations and notes remain in this browser. They are not automatically uploaded to a shared database or verified as official records. Use Save project J S O N to back up the session and share it with collaborators, who can import that project into their own browser.

6. Run the GitHub research demonstration

The linked GitHub research module provides dataset sources, paper P D F links, preparation code, and an evaluation plan. Open its research sample demonstration under Actions, then select Run workflow. Scholars without write access can fork the repository and run it in their fork. The demonstration checks two Landslide for Sense training examples and produces an image and verification report. It prepares data; it does not train a deep learning model.

7. Understand the training example

The example image contains three panels: satellite imagery on the left, a supplied binary landslide annotation in the middle, and the provided slope channel on the right. White pixels in the annotation mark mapped landslide areas in this training sample. They are not predictions made by our software. This benchmark example is not a Maharashtra map. Cite the original Landslide for Sense dataset and preserve its attribution when reusing the example.

8. Plan the next Maharashtra study

For a Maharashtra study, obtain a dated local inventory and independently checked landslide boundaries, then align the satellite images and terrain inputs. Start with a published baseline, document the data split, and keep independent events or regions for evaluation. Report errors and uncertainty as well as aggregate scores. To claim future susceptibility or early warning, use only information available before the event and define the prediction period. The current research module is a starting point for that work, not a completed validation.

EXISTING MAHARASHTRA EXPERIMENT

A starting point in southern Raigad.

The original terrain-only pilot compared Random Forest and logistic regression using five geographic folds and a 1 km training buffer. It is a software experiment with undated inventory records, not a validated probability map.

Public source data in this atlas are NASA COOLR reports. They are distinct from the GSI-attributed mirror used in the pilot. Exact mirror records, trained model files and national predictions are not distributed here.

What the figures can support

Explore reporting patterns, identify missing evidence and plan data appraisal. Reports are not independent failure events or surveyed absences. Boundary vintages differ; location errors and border ambiguity remain visible. Comparison of raw counts across districts does not control for area, population, exposure, observation effort or mapping coverage.

CSV and GeoJSON uploads, edits and notes run locally in your browser. GitHub Pages serves a static application: it does not collect contributions or synchronize a shared database. Share a downloaded project JSON for a collaborator to import, or propose a reviewed change in the repository.
